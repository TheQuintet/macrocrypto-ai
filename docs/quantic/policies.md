# Policies & Standards

Summary of program rules that apply to our Capstone work. When in doubt, follow official course materials; this page is a team reference.

---

## AI use

| Context | Policy |
|---------|--------|
| **Code generation** | ✅ **Encouraged** — generative AI for code and architectural brainstorming |
| **Written documentation** | ❌ **No verbatim AI output** — design docs and similar writing must be **manual** |
| **Citing AI influence** | ✅ Required where AI shaped your documentation or decisions |

### Practical guidelines for our team

- Use AI to prototype, refactor, and explore architecture — then **review and own** every line merged.
- Design and testing documents: write in your own words; note tools or prompts that influenced major decisions.
- Do not paste AI-generated paragraphs into formal docs without rewriting and citing.

---

## Academic integrity

- **Plagiarism** is strictly monitored, including use of others’ code without proper citation.
- Cite external libraries, tutorials, Stack Overflow snippets, and teammate contributions appropriately.
- Violations can result in **disciplinary action**.

### Code attribution

When we use external code or heavy AI assistance on a module, note it in:

- PR description, or
- Code comment / README section, or
- Design document references

---

## Grading

| Score | Meaning |
|-------|---------|
| **0–5 scale** | Official project score |
| **3+** | **Passing** |
| **Below 3** | Does not meet capstone requirements |

Quality bar: the project should read as a **portfolio piece** — clear purpose, solid engineering, and a working demo.

See [Grading & Pass Criteria](./grading.md) for the full pass requirements, how to aim for 4–5, checklists, and common pitfalls.

---

## Documentation standards

Our written deliverables should:

1. Explain **why** we chose an architecture, not only what we built
2. Describe **testing strategy** and what is automated vs. manual
3. Stay **accurate** with the repo and deployed app at submission time
4. Be **readable** by graders who have not been in our Slack

---

## Repository standards

- Share the repo with **`quantic-grader`**
- No secrets in git (use environment variables)
- Meaningful commit messages and PR reviews
- README: install, run, test, deploy

---

## Presentation standards

The **15–20 minute video** must include:

- Live or recorded demo of the working system
- Every member **speaking**, **on camera**, with **government-issued ID** shown

Plan speaking time so all six members contribute meaningfully.
