## 1. Overview

Together, these stages take walk-forward partitioned features, apply outlier-resistant mathematical transformations, and export production-grade artifacts for downstream forecasting models.

## 2. Input Artifacts
Stages 7 and 8 consume the outputs generated by preceding pipeline phases:
* **Validated & Cleaned Feature Store:** The underlying data sourced from `app/data/ml_btc_daily_features.csv`, containing engineered macroeconomic indicators, cryptocurrency metrics, moving averages, volatility indicators, and imputation flags.
* **Walk-Forward Splits & Target Alignment (Stage 6):** The validated feature set undergoes chronological partitioning via `WalkForwardSplitter`—incorporating purge and embargo windows alongside forward target alignment ($y_t = \text{Price}_{t+1}$)—to yield clean training, validation, and test dataframes.

## 3. Stage 7: Feature Scaling and Transformation

### 3.1 Design Rationale
Cryptocurrency metrics and macroeconomic indicators are prone to extreme price shocks, fat-tailed distributions, and liquidity anomalies. Standard normalization methods like `StandardScaler` (Z-score) are heavily distorted by extreme outliers, while `MinMaxScaler` compresses valid distributions into strict bounds.
* **Selected Scaler:** `RobustScaler` (via `scikit-learn`) serves as the default configuration. By utilizing the median and Interquartile Range (IQR) rather than the mean and standard deviation, it effectively mitigates the impact of macroeconomic and crypto volatility.

### 3.2 Automated Column Exclusion Rules
To maintain data integrity and prevent distortion of categorical or binary attributes, the `FeatureScaler` automatically scans and exempts columns based on rules defined in `ScalerConfig`:
* **Target Variables:** `target_next_price` (exempted to preserve natural pricing units for model evaluation).
* **Date & Time Metadata:** `observation_date` and any field ending in `_timestamp`.
* **Binary Status & Imputation Flags:** Fields ending in `_is_missing` or `_is_imputed`.
* **Explicit Exclusions:** Pipeline flags such as `warmup_complete`.

### 3.3 Strict Train-Exclusive Fitting (Zero Data Leakage)
To eliminate look-ahead bias and data leakage:
1. The `FeatureScaler` fits **exclusively on the training partition** (where the training set timestamp index $t \in \text{Train}$).
2. Learned transformation parameters (medians and IQRs) are applied independently to validation, test, and live inference sets.
3. Invoking `.transform()` prior to `.fit()` triggers a protective `ValueError`.

## 4. Stage 8: Final ML-Ready Dataset Packaging

### 4.1 Persistence Strategy
To cleanly decouple the data engineering layer (`data-service`) from the model training and inference stack (`ai-service`), Stage 8 serializes outputs directly to disk:
* **Processed Partitions (`.parquet`):** Apache Parquet is utilized instead of CSV to ensure compressed file sizes, fast I/O throughput, and strict preservation of data types (datetimes, booleans, floats).
* **Fitted Scaler (`.pkl`):** The fitted `FeatureScaler` instance is serialized using `joblib`, guaranteeing that future live inference requests apply identical scaling parameters without pipeline re-execution.

### 4.2 Output Artifact Manifest
Execution of the pipeline orchestrator (`app/ml/pipeline_orchestrator.py`) generates the following file structure under `app/data/processed/`:
1. `train_scaled.parquet` — Scaled training features and aligned targets.
2. `val_scaled.parquet` — Scaled validation features transformed via training statistics.
3. `test_scaled.parquet` — Scaled test features transformed via training statistics.
4. `feature_scaler.pkl` — Serialized `FeatureScaler` object.
